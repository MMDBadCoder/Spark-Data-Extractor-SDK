# Delivery status

This checkout is a source-only implementation for a preconfigured Jupyter environment. It retains `docs/PRD.md` verbatim as the approved specification. Delivery diverges from PRD sections 7 and 10: this handoff does not include a wheel build or Persian Word guide. The installable packaging metadata, packaging manifest, doc-generation script, generated Word guide, and superseded design/assessment/repository/test-report documents were removed to keep delivery focused on the source ZIP. The root `admin.yaml` contains null endpoint placeholders only; deployment administrators must configure it before use, without distributing live endpoints or secrets in customer examples.

The intended client target is Python 3.10.12 with PySpark 3.4.4 and Hadoop 2.10.2. `Query` loads and validates the runtime admin config, then sets `SPARK_REMOTE` before callers import `pyspark.sql.functions.col`. Importing `data_extractor` alone has no side effects. A conflicting pre-existing `SPARK_REMOTE` or a configuration change after construction is rejected. Spark Connect sessions use `.remote(url).appName(name).getOrCreate()` and `stop()` cleanup. Spark 3.4 cancellation support is not assumed; unsupported cancellation and cleanup uncertainty are logged. PySpark 3.4.4 source-only dependency pins were not vendored or verified as a complete offline package list.

Local validation: 25 config/validation/writer/source-import tests pass with `python -m unittest`; a broader 32-test run across config, validation, executor, writer, and source import passes when a small in-memory `requests` stub is supplied. The optional native Spark Column test is skipped because PySpark is not installed in this workspace. CLI/WebHDFS tests need the real `requests` package; local HTTP server tests are blocked by sandbox socket permissions. The regular full-suite command fails on missing `requests`. These unit tests and scaffolds are not evidence of live Spark Connect, HDFS, WebHDFS, remote cancellation, or production-scale behavior. No live endpoints are configured in this workspace. Refer to `SMOKE_TEST.md` for deployment gates and `customer_guide_fa.md` for the novice Jupyter workflow.
