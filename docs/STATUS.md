# Delivery status

This checkout is a source-only implementation for a preconfigured Jupyter environment. It retains `docs/PRD.md` verbatim as the approved specification. Delivery diverges from PRD sections 7 and 10: this handoff does not include a wheel build or Persian Word guide. The installable packaging metadata, packaging manifest, doc-generation script, generated Word guide, and superseded design/assessment/repository/test-report documents were removed to keep delivery focused on the source ZIP. The root `admin.yaml` contains null endpoint placeholders only; deployment administrators must configure it before use, without distributing live endpoints or secrets in customer examples.

Runtime target and lifecycle: Python 3.10.12, PySpark 3.4.4, and the Hadoop 2.10.2 client. After `Query(...)` validates administrator configuration, it sets `SPARK_REMOTE`; users must construct the query before importing `pyspark.sql.functions.col` so PySpark 3.4.4 creates Connect columns. Each run uses the Spark 3.4.4-supported `SparkSession.builder.remote(connect_url).getOrCreate()` API. `session_prefix` remains an accepted administrator setting and is used with query/execution identity in client-side correlation logs; this builder does not apply it as a server application name. The worker attempts `stop()` cleanup on exit and attempts `interruptAll()` on failure/timeout when supported, while logs retain uncertainty about remote cancellation or cleanup. Runtime dependencies are not pinned or bundled in this source-only handoff; the target environment's complete PySpark Connect dependency set must be prepared and verified by the deployment administrator.

The CSV null marker is the literal `\\N`. A real string value equal to that marker collides with null on round-trip, so output is not lossless for that value; this limitation is called out in the Persian customer guide.

Local validation: 56 selected tests passed with `python -m unittest`, comprising 46 config/validation/executor/writer/schema/source-import checks and 10 mocked WebHDFS checks. The latter use a test-scoped in-memory `requests` substitute because this workspace lacks the real package. Full discovery found 63 tests: 59 passed, one optional native Spark Connect test skipped because PySpark is absent, and three local HTTP tests could not start a loopback server because sandbox socket creation is prohibited. Those HTTP integration cases also require the real `requests` package. These checks are not evidence of live Spark Connect, HDFS, WebHDFS, remote cancellation, or production-scale behavior. No live endpoints are configured in this workspace. The synchronous manifest publication step occurs on the caller thread after worker completion and is outside the worker execution deadline; a blocked manifest operation can therefore exceed the configured overall timeout. Refer to `SMOKE_TEST.md` for deployment gates and `customer_guide_fa.md` for the novice Jupyter workflow.
